功能授权 + 数据级授权

权限不是开关，
是一本台账。

谁能调用哪个接口、能看到哪几行数据、一条资源又额外共享给了谁， 在这套原型里都可以在同一屏内读到。角色矩阵、数据范围、归属与共享， 用同一套视觉语言表达，避免把授权拆成互不相干的三张表。

功能授权 Permission

决定“能不能做这件事”。接口、菜单、路由与按钮共用同一组 资源:动作 权限码。

用户×角色×权限码
且

数据授权 Data Scope / ACL

决定“能对哪些数据做”。归属人、角色的查看与管理范围、单个资源的共享授权三者取并集。

owner_id+数据范围+共享 ACL

按评审顺序走一遍

建议按此顺序检查：先看身份与菜单，再看列表过滤，最后看角色配置与共享。

# 页面 路由 所需权限 评审关注点
01 登录 /login 免登录 四种角色的一键体验入口；登录后权限上下文由 /users/me 下发。
02 工作台 / 仅登录 菜单按权限过滤；数据范围摘要与可见资源的统计口径。
03 Agent 管理 /agents agent:view 归属人列、共享标记、行内编辑按钮随 can_manage 出现或消失。
04 Agent 详情 /agents/:id agent:view 共享抽屉、转移归属、当前用户的权限来源说明。
05 Prompt 管理 /prompts prompt:view 同一套归属与行级操作；发布按钮受功能权限控制。
06 知识库 /knowledge knowledge:view 运营可管理全部知识库；开发者只能改自己的与共享给本人的。
07 工具管理 /tools tool:view 启停、测试调用与删除的权限差异。
08 模型管理 /models model:view 平台级资源，只有功能权限，不出现归属列与共享入口。
09 对话日志 /conversations conversation:view 日志跟随所属 Agent 的可见性；后端模块未上线，页面标注口径。
10 数据统计 /analytics analytics:view 只聚合可见 Agent；切换“仅本人”身份后数字随之变化。
11 用户管理 /system/users user:view 角色列、本人行保护、拥有资源时的删除拒绝。
12 角色管理 /system/roles role:view 双 Tab 配置弹窗：模块 × 动作矩阵 + 四类数据范围。
13 权限目录 /system/permissions permission:view 47 条权限只读展示；预留权限标注“未上线”。
14 预留模块 /system/api-keys apikey:view 本期只做菜单与路由控制；上线前的接入要求。
15 403 页 /403 — 展示所需权限码与返回路径；只读身份直访系统页时落到这里。
16 个人中心 /profile 仅登录 只读展示当前角色、权限集合、数据范围与共享给我的资源。
产物一 · 静态页面

HTML + CSS + JavaScript

入口 index.html，共享样式与交互在 assets/app.css 与 assets/app.js。 任意页面可加 ?as=developer、?as=developerSelf、?as=operator、 ?as=viewer 直接以该身份打开；加 ?ghost=1 标出被隐藏的无权限控件。
