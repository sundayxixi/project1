## 一、概述

### 1.1 这套原型要回答什么

这套页面原型不用于演示“好看的表格”，而是把需求文档里最难靠文字讲清的三件事放到界面上：

1. **功能权限如何被看见**：同一组 `资源:动作` 权限码，如何同时控制菜单、路由、按钮与接口提示。
2. **数据范围如何被理解**：为什么同一个列表，管理员看到 7 条、开发者看到 7 条、数据范围收紧到“仅本人”后只剩 3 条。
3. **资源级共享如何被操作**：如何在不改变所有者、不扩大角色范围的前提下，把单个 Agent 或知识库共享给某个人或某个角色。

原型覆盖 16 个页面（另有 1 个原型目录页），对应需求文档第八章页面需求与第九章接口映射，重点验证 FR-08、FR-09、FR-14、FR-15、FR-16、FR-17。

### 1.2 原型边界

- 纯静态 HTML + CSS + JavaScript，不调用任何真实接口。
- 权限与数据范围由前端内置的身份模型模拟，用于评审交互与视觉，不构成实现方案。
- 登录、分页、搜索、弹窗、共享、角色配置等交互可用；数据不持久化（身份选择除外）。
- 后端预留模块（对话日志、数据统计、API 密钥、审计、告警、系统配置）只做菜单、路由与页面骨架。
- 视觉风格针对 RBAC 场景做了“授权台账”方向的探索，是否并入正式产品设计系统由评审决定。

## 二、设计概念：授权台账

### 2.1 概念

RBAC 的界面通常被拆成三个互不相干的页面：角色权限矩阵、用户角色分配、业务列表。使用者需要在脑中拼装“这个人到底能做什么”。这套原型把三者放在同一种视觉语言下：

- **矩阵是台账的表格**：模块 × 动作，斜纹表示未上线的预留模块，勾选格是台账上的印戳。
- **归属是台账的落款**：每条业务资源都带一个方形名章（所有者），共享条目以细边框标签标注级别。
- **权限上下文条是台账的眉批**：每个页面顶部都写明“我是谁、本页需要什么权限、我在这类资源上的有效范围”。

因此页面里的结构性元素都在传递信息，而不是装饰：竖线分隔的是不同的授权维度，斜纹表示未实现，虚线表示运行时不存在，方形章代表归属。

### 2.2 与通用后台模板的差异

设计时刻意避开了几类默认手法：

| 默认手法 | 本原型的处理 |
|---|---|
| 奶油底 + 衬线大标题 + 陶土色强调 | 保留产品既有冷灰底与蓝色强调；衬线只用于标题，不改变整体色调 |
| 近黑底 + 荧光绿/朱红单一强调 | 深色只用于侧边栏与提示条，强调色仍是产品蓝 |
| 报纸式细线、零圆角、密排分栏 | 使用 3px 小圆角与细线表格，但保留企业后台的留白与可读性 |
| SaaS 卡片套件：所有内容切成一模一样的圆角卡片 | 业务列表、管理页都以“一条表格 + 一条页眉”为主，卡片只用于需要分组的面板 |
| 全大写 eyebrow、`A · B · C` 元信息、`→` 按钮后缀 | 不使用；元信息用空格、竖线与状态标签表达 |

### 2.3 方案评审后的修正

初版方案在实现后用截图逐一检查，做了以下修正（保留了修正原因，便于后续判断）：

1. **无权限控件的权限码标签重叠**：最初在每个虚线按钮上方浮出权限码，行内按钮过密时互相覆盖。改为页首的评审说明条 + 悬停 `title` 显示权限码。
2. **弹窗垂直位置不一致**：短弹窗被自动居中、长弹窗顶对齐。改为统一从顶部 48px 开始，长内容在遮罩层内滚动。
3. **列表页顶部与底部重复计数**：去掉工具栏右侧的“共 X 条”，只在分页脚保留计数与数据范围说明。
4. **个人中心数据范围表头与内容不对应**：表头改为“有效范围（查看 / 管理）”与“作用面”，避免把两个维度混在一列。
5. **索引页在窄屏横向溢出**：封面容器改为 `width: 100%` 并允许目录表在容器内横向滚动；顶栏只保留当前页面包屑。
6. **当前账号行操作列为空**：改为显示“不可操作自己”，让规则可见，而不是让一行看起来坏掉。
7. **登录页快捷身份与评审面板文字挤成一行**：给名称与说明补 `display: block`。

## 三、视觉系统

### 3.1 颜色

| Token | 色值 | 用途 |
|---|---|---|
| `--ink` | `#111A26` | 侧边栏、评审面板、深色代码块 |
| `--ink-2` / `--ink-3` | `#1B2735` / `#2A3848` | 深色分层、描边 |
| `--stone` | `#EDF0F4` | 页面底色 |
| `--surface` | `#FFFFFF` | 表格、面板、弹窗 |
| `--surface-2` | `#F7F9FB` | 表头、次级块、禁用底 |
| `--line` | `#DDE4EB` | 常规分隔线 |
| `--line-strong` | `#C6D1DC` | 控件边框、重点分隔 |
| `--text` | `#18222E` | 正文 |
| `--muted` | `#5C6B7C` | 说明、次要信息 |
| `--faint` | `#8795A5` | 标签、占位、极次要信息 |
| `--accent` | `#2563EB` | 主按钮、勾选、当前导航 |
| `--accent-deep` | `#1D4ED8` | 主按钮悬停 |
| `--accent-soft` | `#EDF3FE` | 本人标记、浅蓝底 |
| `--jade` | `#0F7A5F` | 已实现、共享中 |
| `--amber` | `#8A5A00` | 未上线、评审说明 |
| `--danger` | `#B42318` | 删除、禁用 |

配色比例大致为：中性色 90%，深色 8%，强调与状态色 2%。状态色只表达语义，不用于装饰。正文与深色底对比度均达到 WCAG AA；状态同时有文字，不只依赖颜色。

### 3.2 字体

| 角色 | 字体栈 | 用法 |
|---|---|---|
| 标题 | `"Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", Georgia, serif` | 页面标题、弹窗标题、统计大数字、403 印戳 |
| 正文 | `"Inter", "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif` | 正文、表格、控件 |
| 代码 | `ui-monospace, "SFMono-Regular", "Cascadia Mono", Consolas, monospace` | 权限码、资源标识、缓存 key、接口路径 |

字号与字重：

| 层级 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 28px / 1.25 | 600（衬线） |
| 封面主标题 | 42px / 1.3（窄屏 32px） | 600（衬线） |
| 弹窗标题 | 19px / 1.3 | 600（衬线） |
| 正文 | 13px / 1.55 | 400 |
| 表格 | 12.8px | 400 / 600（名称） |
| 标签 / 辅助 | 11.5px、10.5px | 400 / 600 |
| 统计数字 | 25–32px | 600（衬线、等宽数字） |

规则：

- 表格数字统一 `font-variant-numeric: tabular-nums`。
- 权限码只使用等宽字体，不用代码块包裹正文。
- 正文行长控制在 72 个字符以内；登录页论点控制在 30 字左右一行。
- 不把整段正文设为衬线，衬线只承担标题与数字。

### 3.3 间距、圆角与阴影

- 基础间距 4px；常用 8 / 10 / 12 / 14 / 16 / 18 / 22 / 24 / 44px。
- 控件高度：普通 32px，小号 26px，输入 34px，表格行约 44–66px。
- 圆角：控件与表格容器 2px，弹窗 3px；不使用胶囊按钮与 16px 大圆角卡片。
- 阴影：只用于弹窗、抽屉与评审工具；普通面板靠 1px 边框分层。

### 3.4 图标与动效

- 图标为 16px 线性图标，描边 1.6，跟随文字颜色；无彩色图标。
- 动效只用于悬停、选中与弹窗出现，时长 120ms；没有滚动入场动画。
- `prefers-reduced-motion: reduce` 时关闭全部过渡。

## 四、布局与信息架构

### 4.1 应用外壳

```
┌──────────────┬──────────────────────────────────────────────────────┐
│  侧边栏 232   │  顶栏 56：面包屑 · 数据范围摘要 · 个人中心 · 身份      │
│              ├──────────────────────────────────────────────────────┤
│  品牌         │  内容区 24px 内边距，最大宽度 1280                    │
│  平台功能     │                                                      │
│  系统管理     │  衬线页面标题                              操作按钮   │
│              │  权限上下文条：身份 / 本页权限 / 有效范围 / 权限来源   │
│              │  工具栏：搜索、状态、归属                             │
│  用户区       │  数据表面：表头 + 行 + 分页脚                        │
└──────────────┴──────────────────────────────────────────────────────┘
```

- 侧边栏固定 232px，深色；当前项用 2px 竖向蓝条与 16% 透明蓝底，而不是整块蓝色胶囊。
- 顶栏不再重复页面标题，只放面包屑、当前资源的数据范围摘要与身份切换。
- 内容区左对齐；仅空状态、403 与登录页使用居中构图。
- 系统管理分组没有任何可见项时整组隐藏，而不是留下一个空标题。

### 4.2 权限矩阵

```
┌ 模块（吸顶 + 首列吸左） ┬ 查看 ┬ 创建 ┬ 编辑 ┬ 删除 ┬ 发布 ┐
│ Agent 管理              │  ■   │  ■   │  ■   │  □   │  ■   │
│ agent                   │      │      │      │      │      │
│ 模型管理                │  ■   │  □   │  □   │  □   │  —   │
│ …                       │      │      │      │      │      │
│ 对话日志  待上线        │  ■   │  —   │  —   │  —   │  —   │  ← 斜纹底
└─────────────────────────┴──────┴──────┴──────┴──────┴──────┘
```

- 矩阵是页面的视觉核心：细线网格、首列吸左、表头吸顶。
- 勾选格是 18px 方形按钮；选中为蓝底白勾，未选为白底细边框，不适用为短横线。
- 预留模块整行斜纹，并在模块名旁放“待上线”标签；勾选仍可操作，因为菜单/路由控制确实需要它。
- 矩阵下方只放一条说明，不再叠加统计卡。

### 4.3 列表页

- 标题与一行用途说明；右侧最多两个主操作。
- 上下文条固定四格；窄屏降为两格，再窄降为一格。
- 工具栏只保留搜索和两个筛选；计数只在分页脚出现一次。
- 表格首列是资源名 + 资源标识；归属人列使用方形名章；共享状态用细边框标签。
- 行内操作默认右对齐：查看为描边按钮，编辑/发布为文字按钮，删除为红色文字按钮。无权限的操作不渲染。
- 表格底部同时承担分页与口径说明：“已按查看范围过滤，服务端会再次判定”。

## 五、页面设计

### 5.1 原型目录 `index.html`

- **作用**：给评审者一条路径，而不是另一张功能页。
- **结构**：封面论点 → 权限覆盖点阵（47 格，开发者默认持有 18 格）→ 两层授权模型 → 按评审顺序排列的 16 个页面目录 → 两套产物说明。
- **细节**：目录编号是真实的评审顺序，不是装饰性序号；点阵中深色块对应 Agent 的 4 项权限，浅色为其他已持有权限，空白为未持有或预留。
- **截图**：`00-index.png`。

### 5.2 登录 `login.html`

- **权限**：免登录。
- **结构**：左侧深色论点区 + 权限目录点阵；右侧用户名、密码、验证码表单与四个内置角色的快捷体验。
- **规则**：登录仅返回 JWT；权限与数据范围由 `/users/me` 下发。表单说明 `code=401` 的处理方式。
- **截图**：`01-login.png`。

### 5.3 工作台 `dashboard.html`

- **权限**：仅登录。
- **结构**：上下文条 → 四个权限事实（权限码数、角色、Agent 范围、知识库范围）→ 最近活动 → 我的数据范围 → 权限过滤后的快捷入口。
- **细节**：工作台不聚合资源数量，避免在没有后端统计时制造“数字权威”；这里的统计卡全部是当前身份可验证的权限事实。
- **截图**：`02-dashboard.png`。

### 5.4 Agent 列表 `agents.html`

- **权限**：`agent:view`；数据范围按 Agent 计算。
- **结构**：搜索、状态、归属筛选；表格列为 Agent、状态、版本、归属人、最近更新、操作。
- **数据范围表现**：
  - 管理员：7 条，全部可编辑/删除。
  - 开发者（查看全部 / 管理本人）：7 条，只有本人创建的两条出现编辑/发布；没有删除权限。
  - 开发者（仅本人范围）：3 条（本人 2 条 + 共享 1 条），共享行只有“查看”。
  - 只读：7 条，仅“查看”。
- **空状态**：数据范围为本人且没有任何资源时，显示“当前数据范围内暂无数据”而不是“暂无数据”，并提供查看自身范围的入口。
- **截图**：`03-agents-admin.png`、`04-agents-developer.png`、`05-agents-developer-self.png`、`06-agents-viewer-ghost.png`。

### 5.5 Agent 详情 `agent-detail.html`

- **权限**：`agent:view`；共享/转移/编辑需要 `agent:update` + 对该 Agent 的管理数据权限。
- **结构**：配置摘要与提示词预览 → 版本表 → 归属与共享侧栏 → 判定顺序侧栏。
- **关键交互**：共享抽屉（添加用户/角色、改级别、移除）、转移归属弹窗、版本回滚。
- **权限表现**：以管理员打开时三个操作都可用；以开发者李四打开时，因只有该 Agent 的只读共享，共享/转移/编辑都不渲染。
- **截图**：`07-agent-detail.png`、`08-agent-share.png`、`09-agent-transfer.png`。

### 5.6 Prompt 列表 `prompts.html`

- **权限**：`prompt:view`，发布单独受 `prompt:publish` 控制。
- **细节**：开发者默认拥有 Prompt 的删除权限，所以“删除”只受行级管理权限制；这与 Agent 的删除权限形成对比，用来验证权限矩阵不是按模块“一刀切”。
- **截图**：`10-prompts.png`。

### 5.7 知识库 `knowledge.html`

- **权限**：`knowledge:view`；文档与分段继承知识库判定。
- **结构**：文档/分段数量、索引状态（完成/中/失败）、归属人、操作；失败行出现“重试”。
- **数据范围表现**：
  - 运营：6 个知识库全部可编辑，但没有删除权限。
  - 开发者（仅本人）：3 个，其中共享为可管理的“产品知识库”可编辑与共享，共享为只读的“合同模板库”只能查看。
- **共享抽屉**：按需求文档 8.4 的示例，列出李四（可管理）、赵宁（只读）、运营角色（只读）。
- **截图**：`11-knowledge.png`、`12-knowledge-share.png`、`28-knowledge-developer-self.png`、`29-knowledge-operator.png`。

### 5.8 工具列表 `tools.html`

- **权限**：`tool:view`；测试、启停归入 `tool:update`；删除归入 `tool:delete`。
- **细节**：开发者没有删除权限，删除按钮完全不渲染；共享为只读的工具不出现测试/启停。
- **截图**：`13-tools.png`。

### 5.9 模型管理 `models.html`

- **权限**：`model:view` / `create` / `update` / `delete`。
- **细节**：模型与供应商是平台级共享资产，不出现归属列、共享入口与数据范围；开发者在页面上只看到“查看”，所有写按钮消失。这是 NG10 的界面证据。
- **截图**：`14-models.png`。

### 5.10 对话日志 `conversations.html`

- **权限**：`conversation:view`（预留模块）。
- **口径**：仅显示当前用户可见 Agent 产生的会话；列表里的行归属对应 Agent 的所有者，因此切换身份会同步收缩。
- **截图**：`15-conversations.png`。

### 5.11 数据统计 `analytics.html`

- **权限**：`analytics:view`（预留模块）。
- **结构**：四个汇总数（可见 Agent、会话、Token、费用）+ 按 Agent 的明细。
- **细节**：汇总由可见行实时求和；切到“开发者 · 仅本人”时，行数从 7 变为 3，会话从 1,284 变为 678，费用从 ¥455.80 变为 ¥271.70。占比同时重算。
- **截图**：`16-analytics.png`、`30-analytics-developer-self.png`。

### 5.12 用户管理 `system-users.html`

- **权限**：`user:view`；分配角色/禁用需要 `user:update`；删除需要 `user:delete`。
- **结构**：用户、邮箱、角色、拥有资源、状态、最后登录、操作。
- **规则表现**：
  - 当前账号行高亮，显示“本人”标签，禁用与删除不渲染，操作列显示“不可操作自己”。
  - 删除仍拥有资源的用户时，Toast 明确提示“请先转移归属”，并说明资源数量。
  - 分配角色弹窗只做全量覆盖，保存后提示“该用户下一次请求即生效”。
- **截图**：`17-system-users.png`、`18-system-users-roles.png`。

### 5.13 角色管理 `system-roles.html`

- **权限**：`role:view`；配置需要 `role:update`。

## 六、授权交互模型

### 6.1 模拟身份

| key | 用户 | 角色 | 权限数 | Agent 范围（查看/管理） | 知识库范围（查看/管理） |
|---|---|---|---|---|---|
| `admin` | 陈晓 | 管理员 | 47 | ALL / ALL | ALL / ALL |
| `developer` | 李四 | 开发者 | 18 | ALL / SELF | ALL / SELF |
| `developerSelf` | 李四 | 开发者（收紧查看范围） | 18 | SELF / SELF | SELF / SELF |
| `operator` | 王敏 | 运营 | 9 | ALL / SELF | ALL / ALL |
| `viewer` | 赵宁 | 只读 | 7 | ALL / SELF | ALL / SELF |

身份可通过右下角评审面板或 URL `?as=` 指定；选择写入 `localStorage`，刷新后保持。切换身份时整页重新渲染，避免只改按钮不改数据的“假演示”。

### 6.2 功能权限判定

```
can(code) = is_superuser || permissions.includes(code)
```

- 菜单：无权限项不生成 DOM；系统管理分组无任何可见项时整组隐藏。
- 路由：`body[data-page-perm]` 声明的权限码任一满足才渲染，否则 `location.replace('forbidden.html?need=…')`。
- 按钮：无功能权限不渲染（不是置灰）；评审模式可临时以虚线标出，并附悬停提示。
- 预留模块：权限码只控制菜单与路由，页面本身明确说明后端未实现。

### 6.3 数据范围判定（原型实现）

对每一行资源：

```
可见 = is_superuser
      || owner_id = 我
      || 共享给我（view 或 manage）
      || 共享给我的角色
      || 查看范围为 ALL
      || 管理范围为 ALL

可管理 = is_superuser
        || owner_id = 我
        || 共享给我且级别为 manage
        || 共享给我的角色且级别为 manage
        || 管理范围为 ALL
```

列表行按“可见”过滤，操作按钮按“功能权限 AND 可管理”渲染。分页文案、汇总数字、会话占比随之更新。真实实现中这一步必须发生在服务端查询层，原型只为评审模拟。

### 6.4 资源级共享

- 只在详情页或列表行的“共享”入口打开，要求管理数据权限 + `<资源>:update`。
- 抽屉内可以添加用户或角色、选择只读/可管理、修改级别、移除；所有操作以 Toast 提示“立即生效”。
- 不能共享给“所有人”；不能把自己加为共享对象；重复主体更新级别而不是新增。
- 共享不改变所有者与 `created_by`；转移归属后原有共享保留。

### 6.5 角色配置

- 双 Tab 共用同一弹窗，保存按钮只出现一次。
- 矩阵勾选实时更新“已选 N 项”；不同角色打开时加载对应示例集。
- 数据范围选择 CUSTOM 时展开对象标签；切换为 ALL/SELF 时收起。
- 保存提示“配置已更新，对该角色下用户立即生效”。

### 6.6 错误与反馈

- 403：路由级无权限跳转 403 页面；操作级拒绝（原型中用 Toast 示例）文案区分“缺少功能权限”与“无权访问该资源”。
- 401：原型不实现 token 过期，登录页说明会清空 token 并回到登录。
- 危险操作：删除内置角色/仍拥有资源的用户时给出具体原因，而不是只显示一个灰色按钮。

## 七、核心组件规格

### 7.1 权限上下文条（Context strip）

- 四列：当前身份 / 本页功能权限 / 有效数据范围 / 权限来源入口。
- 内边距 10×14，竖线分隔，无阴影；标签 10.5px 浅灰，内容 12.5px。
- 身份包含方形名章、姓名、角色标签；`is_superuser` 额外显示系统标签。
- 数据范围用“查看 X / 管理 Y”表达，资源页展示对应资源，非资源页说明“平台级资源 · 仅受功能权限控制”。
- 工作台/个人中心用四个小标签展示四类资源的范围，避免过宽。

### 7.2 权限矩阵（Matrix）

- 首列 236px，动作列等宽；表头吸顶，首列吸左。
- 行高 42px；模块名 12.5px，资源码 10.5px 等宽浅灰。
- 勾选按钮 18px，选中蓝底白勾；不适用为短横线；预留行斜纹底。
- 矩阵最小宽度 700px，容器内横向滚动，不撑破页面。
- 勾选数量在 Tab 与弹窗脚同时显示，修改即时同步。

### 7.3 数据范围编辑器

- 4 行 × 2 列下拉，资源列带资源码。
- 选项固定为全部数据 / 仅本人 / 指定用户/角色。
- CUSTOM 时展示标签：姓名 + 主体类型 + 移除按钮，末尾为虚线“添加用户或角色”按钮。
- 任一范围使用 CUSTOM 时展开标签区；说明文字强调“范围不替代功能权限”。

### 7.4 共享抽屉

- 宽 480px，右侧滑出，遮罩 32% 深色。
- 顶部说明“共享只解决数据层”；底部固定说明“不能共享给所有人”。
- 添加表单：输入框（带用户/角色候选）、级别下拉、添加按钮。
- 列表行：主体名章、姓名、类型、级别下拉、移除；底部显示授予人与最近变更时间。
- 空列表时显示“尚未共享给任何人”，而不是空白。

### 7.5 归属名章与标签

- 名章 20×20，1px 边框，1px 圆角，衬线首字；当前用户的名章使用蓝色描边与浅蓝底，并在姓名后加“（我）”。
- 共享标签：`共享 · 只读` / `共享 · 可管理`；内置角色标签“内置”；预留“待上线”；未实现权限“未上线”；当前行“本人”。
- 标签字号 10.5px、1px 边框、2px 圆角，不使用胶囊。

### 7.6 空状态

- 1px 虚线框 + 34px 线性图标 + 衬线标题 + 两行解释 + 一个动作。
- 文案区分“真的没有数据”和“数据范围导致看不到”：
  - 业务列表：“当前数据范围内暂无数据。资源可能存在，只是不在你的查看范围内。”
  - 统计：“当前数据范围内暂无可统计的数据。”

### 7.7 403 页面

- 78px 方形印戳、旋转 -5°，衬线“403”。
- 明确列出所需权限码与请求页面；提供返回工作台、查看权限、返回原型目录。
- 底部说明 403 不区分资源不存在与无权限。

### 7.8 评审工具

- 右下角 32px 深色按钮，展开 304px 面板。
- 五种身份单选、无权限控件开关、权限码数量、Agent/知识库范围摘要。
- 面板状态在会话内保持；`?tool=0` 可隐藏，便于截图。

## 十二、设计自检与遗留问题

### 12.1 克制检查

- 每页只有一个强元素：矩阵页是矩阵，列表页是数据表，登录页是论点 + 点阵，403 页是印戳。
- 强调色只出现在主操作、当前导航、勾选与“本人”标记；其余状态用中性色与语义色。
- 除弹窗、抽屉与评审工具外不使用阴影；除矩阵、代码块与提示条外不使用底纹。
- 没有页面入场动画，避免把评审注意力从内容上移开。

### 12.2 需要评审确认的问题

1. **衬线标题是否并入产品设计系统**：当前只在 RBAC 原型中使用；若产品希望保持全无衬线，可仅保留矩阵与上下文条的结构创新。
2. **CUSTOM 目标的交互**：需求模型允许查看与管理各自配置指定对象，当前原型只展示一套对象标签（挂在知识库查看范围下）。正式设计需要明确“分别配置”还是“共用一套对象”。
3. **数据级 403 的表现**：原型复用了统一的 403 页面；是否需要针对“资源无权访问”提供更轻的行内或无权限面板，需要产品确认。
4. **预留模块的菜单呈现**：当前保留入口并标琥珀点；若评审认为会误导，可改为“更多（未上线）”折叠组。
5. **移动端密集表格**：保留横向滚动；若移动端是一等场景，需要单独设计列优先级或卡片化行。

### 12.3 原型限制

- 无真实接口；权限、共享、保存均为前端模拟，刷新后除身份外不保留。
- 分页只展示第 1 页；搜索与筛选可用但不做真实查询。
- 一个身份对应一个示例用户；无法在原型内登录自定义用户。
- 角色配置弹窗内置 5 个角色的示例权限集，不覆盖全部 47 条权限的逐条勾选演示（权限目录页展示全量）。
- 无加载骨架、无空搜索态、无焦点陷阱。
- 统计页与对话页为预留模块，页面内容仅用于说明口径与权限控制。
- 字体依赖系统回退：Windows 使用 SimSun 衬线，macOS 使用 Songti，Linux 可能回退到 Noto Serif；字形会有差异。
- 截图由 Playwright + Edge 在 1440 宽下生成，非高 DPI（1x），用于文档评审而非视觉交付。
